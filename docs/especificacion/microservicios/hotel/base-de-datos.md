# Hotel — base de datos, procedimientos y seeds

BD `hotel_db`. Datos físicos y catálogo público. [Convenciones comunes](../../03-contrato-comun.md); campos ? admiten NULL.

## Tablas

| Tabla | Columnas |
|---|---|
| hotel | id:int PK identity; slug:varchar(80) UNIQUE; nombre:varchar(120); descripcion:varchar(300); direccion:varchar(200); ciudad:varchar(80); telefono:varchar(20); correo_contacto:varchar(254); imagen_url:varchar(500)?; imagen_alt:varchar(150)?; estado:boolean; publicado:boolean; version:bigint; created_at:timestamptz |
| categoria | id:int PK identity; descripcion:varchar(80) UNIQUE; detalle:varchar(500); capacidad:int CHECK 1..10; estado:boolean; version:bigint |
| piso | id:int PK identity; id_hotel:int FK hotel; descripcion:varchar(80); estado:boolean; version:bigint; UNIQUE(id_hotel,descripcion) |
| estado_habitacion | id:int PK fijo; codigo:varchar(30) UNIQUE; descripcion:varchar(80); estado:boolean; version:bigint |
| habitacion | id:int PK identity; id_hotel:int FK; id_piso:int FK; id_categoria:int FK; numero:varchar(10); detalle:varchar(500); precio:numeric(12,2)>0; id_estado_habitacion:int FK; estado:boolean; publicada:boolean; version:bigint; last_cleaning_room_version:bigint default 0; único parcial UNIQUE(id_hotel,numero) WHERE estado (el número se reutiliza tras la baja) |

| ocupacion_projection | id_habitacion:int PK FK; id_recepcion:int?; estado_estadia:varchar(16); room_version:bigint; updated_at:timestamptz. Solo visual |
| operacion_habitacion | block_id:uuid PK; id_habitacion:int FK; tipo:varchar(20) MANTENIMIENTO/BAJA; estado:varchar(20) PREPARANDO/APLICADA/LIBERADA/RECHAZADA; request:jsonb; attempts:int; next_attempt_at:timestamptz |
| api_idempotency, outbox, inbox, audit_log | Comunes |

Validar piso de la misma sede con UNIQUE piso(id,id_hotel) y FK habitacion(id_piso,id_hotel) REFERENCES piso(id,id_hotel). No se deja esta regla al frontend. Índices habitaciones por sede/categoría/activo y limpieza por habitación/estado; UNIQUE parcial una limpieza PENDIENTE por habitación. Un mismo número 101 puede existir en sedes diferentes. El número de una habitación dada de baja puede reutilizarse en otra habitación nueva de la misma sede (índice único parcial solo sobre activas); el histórico se identifica por idHabitacion y snapshots, nunca por número.

Códigos físicos fijos: 1 LISTA, 2 EN_LIMPIEZA, 3 MANTENIMIENTO. NO reutilizar numéricamente los estados legacy: antes 2 significaba OCUPADO. Migración transforma por semántica, no copia IDs a ciegas. Ocupación no es fila del catálogo físico.

## DDL de referencia

Fuente única; los scripts Flyway se derivan de aquí:

```sql
CREATE TABLE hotel (
  id              int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  slug            varchar(80)  NOT NULL UNIQUE CHECK (slug ~ '^[a-z0-9-]+$'),
  nombre          varchar(120) NOT NULL,
  descripcion     varchar(300) NOT NULL,
  direccion       varchar(200) NOT NULL,
  ciudad          varchar(80)  NOT NULL,
  telefono        varchar(20)  NOT NULL,
  correo_contacto varchar(254) NOT NULL,
  imagen_url      varchar(500),
  imagen_alt      varchar(150),
  estado          boolean      NOT NULL DEFAULT true,
  publicado       boolean      NOT NULL DEFAULT false,
  version         bigint       NOT NULL DEFAULT 1,
  created_at      timestamptz  NOT NULL DEFAULT now()
);

CREATE TABLE categoria (
  id          int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  descripcion varchar(80)  NOT NULL UNIQUE,
  detalle     varchar(500) NOT NULL,
  capacidad   int          NOT NULL CHECK (capacidad BETWEEN 1 AND 10),
  estado      boolean      NOT NULL DEFAULT true,
  version     bigint       NOT NULL DEFAULT 1
);

CREATE TABLE piso (
  id          int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_hotel    int          NOT NULL REFERENCES hotel(id),
  descripcion varchar(80)  NOT NULL,
  estado      boolean      NOT NULL DEFAULT true,
  version     bigint       NOT NULL DEFAULT 1,
  UNIQUE (id_hotel, descripcion),
  UNIQUE (id, id_hotel)             -- referencia compuesta desde habitacion
);

CREATE TABLE estado_habitacion (
  id          int PRIMARY KEY,      -- 1 LISTA, 2 EN_LIMPIEZA, 3 MANTENIMIENTO
  codigo      varchar(30) NOT NULL UNIQUE,
  descripcion varchar(80) NOT NULL,
  estado      boolean     NOT NULL DEFAULT true,
  version     bigint      NOT NULL DEFAULT 1
);

CREATE TABLE habitacion (
  id                         int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_hotel                   int           NOT NULL,
  id_piso                    int           NOT NULL,
  id_categoria               int           NOT NULL REFERENCES categoria(id),
  numero                     varchar(10)   NOT NULL,
  detalle                    varchar(500)  NOT NULL,
  precio                     numeric(12,2) NOT NULL CHECK (precio > 0),
  id_estado_habitacion       int           NOT NULL REFERENCES estado_habitacion(id),
  estado                     boolean       NOT NULL DEFAULT true,
  publicada                  boolean       NOT NULL DEFAULT false,
  version                    bigint        NOT NULL DEFAULT 1,
  last_cleaning_room_version bigint        NOT NULL DEFAULT 0,
  FOREIGN KEY (id_piso, id_hotel) REFERENCES piso (id, id_hotel)
);
CREATE UNIQUE INDEX uq_habitacion_numero_activa ON habitacion (id_hotel, numero) WHERE estado;
CREATE INDEX ix_habitacion_sede_categoria ON habitacion (id_hotel, id_categoria, estado);

CREATE TABLE imagen_habitacion (
  id            int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_habitacion int          NOT NULL REFERENCES habitacion(id),
  url           varchar(500) NOT NULL,
  alt           varchar(150) NOT NULL,
  orden         int          NOT NULL,
  UNIQUE (id_habitacion, orden)
);

-- La sede también es una imagen de catálogo: una sola foto principal, opcional.
-- CHECK: la descripción alternativa acompaña a la imagen, nunca va sola.
ALTER TABLE hotel
  ADD CONSTRAINT ck_hotel_imagen_alt
  CHECK (imagen_url IS NULL OR imagen_alt IS NOT NULL);

CREATE TABLE limpieza (
  cleaning_cycle_id uuid PRIMARY KEY,
  id_habitacion     int         NOT NULL REFERENCES habitacion(id),
  id_recepcion      int         NOT NULL,
  room_version      bigint      NOT NULL,
  estado            varchar(20) NOT NULL CHECK (estado IN ('PENDIENTE','COMPLETADA')),
  created_at        timestamptz NOT NULL DEFAULT now(),
  completed_at      timestamptz,
  version           bigint      NOT NULL DEFAULT 1,
  CHECK (estado <> 'COMPLETADA' OR completed_at IS NOT NULL)
);
CREATE UNIQUE INDEX uq_limpieza_pendiente ON limpieza (id_habitacion) WHERE estado = 'PENDIENTE';
CREATE INDEX ix_limpieza_habitacion_estado ON limpieza (id_habitacion, estado);

CREATE TABLE ocupacion_projection (
  id_habitacion  int PRIMARY KEY,
  id_recepcion   int,
  estado_estadia varchar(16) NOT NULL,
  room_version   bigint      NOT NULL,
  updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE operacion_habitacion (
  block_id        uuid PRIMARY KEY,
  id_habitacion   int         NOT NULL REFERENCES habitacion(id),
  tipo            varchar(20) NOT NULL CHECK (tipo IN ('MANTENIMIENTO','BAJA')),
  estado          varchar(20) NOT NULL CHECK (estado IN ('PREPARANDO','APLICADA','LIBERADA','RECHAZADA')),
  request         jsonb       NOT NULL,
  attempts        int         NOT NULL DEFAULT 0,
  next_attempt_at timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_operacion_vigente ON operacion_habitacion (id_habitacion)
  WHERE estado IN ('PREPARANDO','APLICADA');
CREATE INDEX ix_operacion_recuperacion ON operacion_habitacion (estado, next_attempt_at);
```

`api_idempotency`, `outbox`, `inbox` y `audit_log` usan el DDL común de [`03-contrato-comun.md`](../../03-contrato-comun.md).

## Esquemas JSONB

`request` de `operacion_habitacion` (inmutable; el `blockId` es la PK y no se repite dentro):

```json
{"idHabitacion":101,"idHotel":1,"tipo":"MANTENIMIENTO","motivo":"Revisión de aire acondicionado","requestedAt":"2026-10-05T16:00:00Z"}
```

Obligatorios: `idHabitacion`, `idHotel`, `tipo`, `motivo` (1..300) y `requestedAt`. La operación `BAJA` usa el mismo esquema con `tipo:"BAJA"`.

## Procedimientos

| Firma | Comportamiento |
|---|---|
| fn_habitacion_guardar(p_id int?,p_datos jsonb,p_version bigint?) RETURNS habitacion | Catálogo/precio/imágenes; comprueba sede/piso/categoría; no permite cambiar físico ni sede/número desde su creación |
| sp_limpieza_solicitar(p_ciclo uuid,p_habitacion int,p_recepcion int,p_room_version bigint) | Inbox+upsert ciclo; valida tupla; compara/actualiza last_cleaning_room_version; EN_LIMPIEZA; duplicados/viejos no reabren ciclos completos |
| sp_limpieza_completar(p_ciclo uuid,p_habitacion int,p_version bigint) | Lock habitación y luego tarea, mismo orden que solicitar; valida ciclo/habitación/sede y version tarea; PENDIENTE → COMPLETADA, físico LISTA, incrementa ambas versiones; evento con cleaningRoomVersion de la tarea |
| sp_habitacion_aplicar_bloqueo(p_block uuid,p_tipo varchar) | Solo después de Feign exitoso; CAS PREPARANDO → APLICADA; MANTENIMIENTO o baja lógica; LIBERADA/RECHAZADA no reaplican |
| sp_habitacion_habilitar(p_block uuid) | Operación aplicada; LISTA, estado=true; emite habilitación correlacionada |
| sp_hotel_desactivar(p_id int,p_version bigint) | Solo si no quedan habitaciones activas |
| fn_catalogo_publico(p_slug varchar?,p_categoria int?) RETURNS TABLE(id_hotel int,slug varchar,nombre varchar,id_categoria int,descripcion varchar,capacidad int,precio_desde numeric,imagenes jsonb) | Solo sedes publicadas/activas y categorías con habitaciones publicadas/activas; precio mínimo y galería curada, no ocupación |

Altas/reactivaciones/cambios de habitación y bajas de hotel/categoría/piso usan la misma disciplina local: lock de padres en orden hotel → categoria → piso (IDs ascendentes dentro de cada tabla), después habitaciones. Baja verifica ausencia de habitaciones activas dentro del lock; alta/reactivación verifica padres activos. No hacer comprobación de dependencias fuera de esa transacción. Operaciones de limpieza usan habitación → tarea; nunca toman después un lock de padre.

JPA para CRUD de sede/categoría/piso y lectura HotelPublico; fn_catalogo_publico entrega categorías/tarifa/galería agrupadas y el service añade detalle de categoria para CategoriaPublica. Filtros nulos devuelven todos los publicados; nunca datos operativos de cada habitación. No invoca reception dentro de SQL.

La imagen de la sede se guarda en `hotel` (`imagen_url`, `imagen_alt`) y no en una tabla aparte: la landing muestra una sola foto principal por sede. Se valida con la regla del contrato común (https de la lista permitida o `/assets/`, ≤ 500; alt ≤ 150) en el mismo punto que las imágenes de habitación, y `HotelPublico` la expone como `imagenUrl`/`imagenAlt` opcionales. Una sede sin imagen se sirve con ambos campos nulos y la landing cae al fallback neutro.

La galería de la categoría pública se arma con las imágenes de sus habitaciones publicadas y activas, en orden de `orden` y con tope de 10; una habitación sin imágenes no aporta ninguna, así que una categoría puede quedarse sin galería. El seed inicial garantiza al menos una imagen por habitación de cada sede para que ninguna ficha pública aparezca vacía.

Al persistir PREPARANDO, otras mutaciones físicas/catálogo de esa habitación devuelven 409 hasta aplicar o rechazar la operación. Índice único parcial: una operación PREPARANDO/APLICADA no liberada por habitación. La baja conserva blockId hasta reactivación. Reception gate se obtiene por Feign antes de mantenimiento/baja, fuera de transacción SQL. Jobs recuperan operacion_habitacion PREPARANDO; nunca se “arregla” desocupando una habitación por SQL.

No sembrar “ocupado” sin estadía. No restablecer rooms de una presentación ya operada al reejecutar seeds.

## Verificación

La sede sembrada tiene `imagenUrl` no nula y `imagen_alt` presente (el CHECK lo exige); una sede creada sin imagen devuelve ambos campos nulos y la landing no rompe. `GET /api/public/hoteles/lima-centro/categorias` devuelve `imagenes` no vacío para las dos categorías. Una habitación con `publicada=false` no aporta imágenes a la galería pública. Una URL con esquema distinto de `https` o ruta `/assets/` se rechaza con 400.
